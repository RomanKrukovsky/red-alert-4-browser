## Цель реконструкции

Интерфейс должен выглядеть как дорогой, мрачный, высокотехнологичный интерфейс современной AAA RTS во вселенной альтернативной холодной войны.

Обязательные визуальные свойства:

* плотный интерфейс без ощущения пустого веб-сайта;
* тёмные металлические и стеклянные поверхности;
* тонкие светящиеся контуры;
* красные, синие, зелёно-золотые и фиолетовые фракционные темы;
* военные схемы, сетки, линии, карты и телеметрия;
* скошенные углы;
* многослойные рамки;
* глубокие тени;
* внутреннее свечение;
* управляемый bloom;
* текстурированные поверхности;
* фракционные знаки;
* визуальная глубина;
* состояние активной системы;
* ощущение рабочего командного терминала;
* отсутствие стандартного вида HTML-кнопок;
* отсутствие типичного SaaS-интерфейса;
* отсутствие чрезмерно округлых карточек;
* отсутствие мобильного Material Design;
* отсутствие generic Tailwind-dashboard эстетики.

Интерфейс не должен выглядеть как набор обычных прямоугольников с `border-radius: 8px`. Формы должны строиться через CSS `clip-path`, SVG, маски, псевдоэлементы, многослойные границы, декоративные углы и фракционные орнаменты.

## Запрет на визуальную самодеятельность

Не меняй композицию референсов, чтобы она стала «современнее» или «чище». Не сокращай количество элементов только потому, что интерфейс кажется плотным. Не переставляй миникарту, строительную панель, карточку выделенного объекта или командные кнопки по собственному вкусу.

Если на референсе элемент расположен справа, он должен оставаться справа. Если HUD занимает значительную часть нижней области, не заменяй его маленькой плавающей панелью. Если меню использует крупную вертикальную навигацию слева, не превращай её в горизонтальный navbar.

Не используй shadcn-компоненты, стандартные Bootstrap-карточки или готовую dashboard-тему как финальный внешний вид. Разрешено использовать базовые библиотеки для поведения, но финальное оформление должно точно соответствовать референсам.

## Технический процесс визуального сравнения

Создай автоматизированный процесс снятия скриншотов реализованных экранов в тех же размерах, что и референсы.

Добавь команды:

```bash
pnpm ui:references
pnpm ui:screenshots
pnpm ui:compare
pnpm ui:test
```

`ui:references` должен проверить наличие `1.png–24.png`, прочитать размеры и сформировать каталог.

`ui:screenshots` должен запускать приложение через Playwright и снимать каждый реализованный экран при viewport:

```text
1672×941
```

Также снимай дополнительные размеры:

```text
1920×1080
2560×1440
1440×900
1366×768
```

`ui:compare` должен создавать:

* эталонный скриншот;
* скриншот реализации;
* наложение с прозрачностью;
* difference image;
* базовую числовую метрику различия.

Не пытайся бессмысленно добиться полного математического совпадения фонового 3D-рендера. Оценивай отдельно геометрию UI: положение панелей, размеры, отступы, шрифты, кнопки, цвета и композицию.

Создай каталог:

```text
artifacts/ui-comparison/
```

со структурой:

```text
screen-01/
  reference.png
  implementation.png
  overlay.png
  difference.png
  report.json
```

Повтори для каждого экрана.

Используй ViewModels. Не позволяй React читать внутренние mutable-структуры sim-core напрямую.


Не передавай в React позиции каждого юнита тридцать раз в секунду. Миникарта может получать агрегированное или canvas-ориентированное состояние с ограниченной частотой.

Все декоративные растровые элементы должны быть:

## Производительность

HUD не должен снижать FPS игры.

Проверь:

* React render count;
* стоимость backdrop-filter;
* количество SVG filters;
* количество одновременно анимируемых box-shadow;
* canvas minimap;
* обновление progress;
* списки юнитов;
* tooltips;
* видеоэффекты;
* blur.

Не используй тяжёлый `backdrop-filter` на десятках вложенных элементов. Не анимируй большие полноэкранные blur-слои каждый кадр.

Цель:

* стабильные 60 FPS на нормальном компьютере;
* отсутствие покадрового React rerender;
* HUD update не чаще необходимого;
* отсутствие layout thrashing;
* отсутствие постоянного роста памяти.

## Обязательные критерии готовности

6. Миникарта работает.
7. Производственная панель работает.
8. Карточка выделения работает.
9. Пауза работает.
10. Victory и Defeat работают.
11. На 1672×941 композиция максимально совпадает с референсами.
12. Созданы comparison images.
13. Нет стандартного generic dashboard вида.
14. Нет emoji и случайных иконок.
15. Нет ошибок React.
16. Нет ошибок в консоли.
17. `pnpm build` проходит.
18. UI-тесты проходят.
19. Детерминированные тесты sim-core продолжают проходить.
20. Создан отдельный git-коммит.

В конце выдай отчёт:
